# 齿轮组选配 Web 应用（手摇机械装置试制辅助）

包含两个页面：

- **单台选配**（`index.html`）：输入**目标输出转速比**、**允许相对误差**和 2～12 枚**带唯一编号与齿数的现有齿轮**，
  在 **1～3 级传动**内穷举搜索（每级选一枚主动轮 + 一枚从动轮，一枚齿轮在整套方案中至多使用一次），只返回误差达标的方案。
- **批量装配**（`batch.html`）：一次输入 **2～3 台装置**各自的目标速比与容差，**共用同一份齿轮清单**；
  每枚实物齿轮在整批中至多分配一次，自动求互不冲突的全局最优分配。

单台与批量都做到：

- 实际转速比以 **精确分数（BigInt）** 计算，无浮点误差
- 无解/未满足时给出明确提示
- 展示每级配对（编号/齿数）、每级速比、总实际转速比（分数 + 小数）与相对误差

## 一键启动（Docker Compose，自动安装依赖并构建）

```bash
docker compose up --build
```

启动后访问：

- 单台选配： **http://localhost:3000**（根路径 `/` 即单台页）
- 批量装配： **http://localhost:3000/batch.html**

两个页面顶部均有导航可互相切换。后台运行可用 `docker compose up --build -d`，停止用 `docker compose down`。

> 依赖安装（`npm ci`）已写入镜像构建过程，首次启动自动完成，无需手动安装。

## 本地直接运行（需 Node.js ≥ 18）

```bash
npm install
npm start
```

- 单台选配： http://localhost:3000
- 批量装配： http://localhost:3000/batch.html

`npm test` 可运行核心算法自检（单台枚举、批量分配、互不冲突等）。

## 必要配置（环境变量）

| 变量 | 说明 | 默认值 |
| --- | --- | --- |
| `PORT` | 容器内服务监听端口（一般无需修改） | `3000` |
| `APP_PORT` | Compose 映射到宿主机的端口，按需覆盖，例如 `APP_PORT=8080 docker compose up --build` | `3000` |

例如改用宿主机 8080 端口：

```bash
APP_PORT=8080 docker compose up --build   # 访问 http://localhost:8080（批量页 /batch.html）
```

## 使用说明

### 单台选配

1. 填写**目标输出转速比**（输出轴 / 输入轴）：支持小数与分数，如 `0.0833`、`1/12`、`4`。
2. 填写**允许相对误差**：支持百分数 `5%` 或小数 `0.05`（二者等价，表示 5%）；填 `0%` 表示要求精确匹配。
3. 录入 2～12 枚齿轮：每行一个**唯一编号**（如 `G1`）与**正整数齿数**，可随时增删，或点“填入示例”。
4. 点击“开始选配”，结果区按排序规则列出达标方案，第一条标记为“最优”。
5. 若无任何达标组合，页面会明确提示无解，并建议放宽误差或增加齿轮。

单台方案排序：**级数最少 → 相对误差最小 → 齿轮编号序列（自然字典序，G2 在 G10 前）**。
结果最多展示 300 条（达标方案更多时提示“已截断”，但 `total` 仍是全部达标条数）。

### 批量装配

1. 在“装置清单”中维护 **2～3 台装置**（可增删，最少 2 台、最多 3 台），逐台填写目标速比与容差；
   装置按填写先后作为**输入顺序**（决胜时使用）。
2. 录入一份 **2～12 枚的共用齿轮清单**（规则同单台），点“填入示例”可快速体验。
3. 点击“开始批量装配”，结果区按装置顺序逐台展示：
   - **已满足**：选中的配对（级数、各级主动/从动轮、实际速比、相对误差）；
   - **未满足**：说明是该台本就无达标配对，还是齿轮为保证“达标台数最多”而优先分给了其他装置；
   - 底部列出全部**未用齿轮**。
4. 每台还会展示“枚举到达标配对数 / 按占用齿轮集合保留的最优候选数”，
   候选来自对各台**全部达标配对**的穷举，**不是**单台搜索接口截断后的前 300 条。

## HTTP 接口

### `POST /api/search`（单台）

```json
{
  "target": "1/12",
  "tolerance": "5%",
  "gears": [
    { "id": "G1", "teeth": 10 },
    { "id": "G8", "teeth": 60 }
  ]
}
```

返回中 `total` 为达标方案总数，`results` 按级数/误差/编号排序后最多返回 300 条
（`truncated: true` 时表示已截断）；`total: 0` 即无解。

### `POST /api/batch`（批量装配）

```json
{
  "devices": [
    { "target": "1/12", "tolerance": "5%" },
    { "target": "1/6",  "tolerance": "5%" },
    { "target": "1/5",  "tolerance": "5%" }
  ],
  "gears": [
    { "id": "G1", "teeth": 10 },
    { "id": "G8", "teeth": 60 }
  ]
}
```

`devices` 长度必须为 **2～3**。返回摘要：

- `satisfiedCount` / `deviceCount`：达标台数 / 总台数；
- `totalStages`：各台选中配对的级数之和；
- `errorSum` / `errorSumPercent`：各台相对误差之和（精确分数 + 百分数）；
- `devices[]`：按输入顺序逐台给出目标、容差、`totalMatches`（全部达标配对数）、
  `candidateCount`（按占用齿轮集合去重后的候选数）、`satisfied` 与 `selection`（未满足为 `null`）；
- `usedGears` / `unusedGears`：已分配 / 未分配的齿轮。

## 批量装配的计算与决胜规则

- 单台口径与单台搜索完全一致：1～3 级、每级两轮，速比 = ∏(主动轮齿数/从动轮齿数)，
  相对误差 = |实际速比 − 目标速比| / 目标速比，全程精确分数比较；“仅各级排列顺序不同”的方案归一为一条。
- 对每台枚举**全部**达标配对，按其**占用齿轮集合**分组，同一集合只保留一个最优候选
  （级数少 → 相对误差小 → 编号自然序）。
- 以齿轮位图做动态规划，在“任一枚实物齿轮整批至多使用一次”的约束下组合各台候选，按以下**字典序**求全局最优：
  1. **达标台数最多**；
  2. **总级数最少**；
  3. **相对误差之和最小**（各台相对误差以精确分数相加比较）；
  4. 仍并列时，按**装置输入顺序**逐台、再按**齿轮编号自然序**稳定决胜。
- 若不可能让所有装置同时达标，会优先保证靠前目标（达标台数最多），未能满足的装置标记为“未满足”，其齿轮不被占用。
