# 齿轮组选配 Web 应用（手摇机械装置试制辅助）

输入**目标输出转速比**、**允许相对误差**和 2～12 枚**带唯一编号与齿数的现有齿轮**，
系统在 **1～3 级传动**内穷举搜索（每级选一枚主动轮 + 一枚从动轮，一枚齿轮在整套方案中至多使用一次），
只返回误差达标的方案。

- 实际转速比以 **精确分数（BigInt）** 计算，无浮点误差
- 方案排序：**级数最少 → 相对误差最小 → 齿轮编号序列（自然字典序）**
- 无解时给出明确提示
- 展示每级配对（编号/齿数）、每级速比、总实际转速比（分数 + 小数）与相对误差

## 一键启动（Docker Compose，自动安装依赖并构建）

```bash
docker compose up --build
```

启动后访问： **http://localhost:3000**

后台运行可用 `docker compose up --build -d`，停止用 `docker compose down`。

> 依赖安装（`npm ci`）已写入镜像构建过程，首次启动自动完成，无需手动安装。

## 本地直接运行（需 Node.js ≥ 18）

```bash
npm install
npm start
```

访问 http://localhost:3000

## 必要配置（环境变量）

| 变量 | 说明 | 默认值 |
| --- | --- | --- |
| `PORT` | 容器内服务监听端口（一般无需修改） | `3000` |
| `APP_PORT` | Compose 映射到宿主机的端口，按需覆盖，例如 `APP_PORT=8080 docker compose up --build` | `3000` |

例如改用宿主机 8080 端口：

```bash
APP_PORT=8080 docker compose up --build   # 访问 http://localhost:8080
```

## 使用说明

1. 填写**目标输出转速比**（输出轴 / 输入轴）：支持小数与分数，如 `0.0833`、`1/12`、`4`。
2. 填写**允许相对误差**：支持百分数 `5%` 或小数 `0.05`（二者等价，表示 5%）；填 `0%` 表示要求精确匹配。
3. 录入 2～12 枚齿轮：每行一个**唯一编号**（如 `G1`）与**正整数齿数**，可随时增删，或点“填入示例”。
4. 点击“开始选配”，结果区按排序规则列出达标方案，第一条标记为“最优”。
5. 若无任何达标组合，页面会明确提示无解，并建议放宽误差或增加齿轮。

## HTTP 接口

`POST /api/search`

```json
{
  "target": "1/12",
  "tolerance": "5%",
  "gears": [
    { "id": "G1", "teeth": 10 },
    { "id": "G8", "teeth": 60 }
  ]
}
```

返回中 `total` 为达标方案总数，`results` 按级数/误差/编号排序后最多返回 300 条
（`truncated: true` 时表示已截断）；`total: 0` 即无解。

## 计算与排序规则

- 每级转速比 = 主动轮齿数 / 从动轮齿数；总速比 = 各级速比之积（全程约分分数）。
- 相对误差 = |实际速比 − 目标速比| / 目标速比，同样以分数比较，达标条件：相对误差 ≤ 允许值。
- “仅各级排列顺序不同”的同一配对方案只保留一条（按主动轮编号归一化）。
- 并列方案按各级 (主动轮编号, 从动轮编号) 序列做自然序比较（`G2` 排在 `G10` 之前）。
- 12 枚齿轮最坏情况枚举约 10 万量级方案，秒级完成。
